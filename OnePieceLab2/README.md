# Лабораторна робота №2 — принципи ООП у C#

**Тема:** модифікація лабораторної №1 у стилі «Ван Піс» (імена українською).  
**Мова:** C# / .NET 8.0.  
**Інструмент:** Visual Studio Code.

## Швидкий запуск у VS Code

1. Розпакуй архів `OnePieceLab2.zip`.
2. У VS Code вибери **File → Open Folder...** та відкрий саме папку `OnePieceLab2` (в ній має бути файл `OnePieceLab2.csproj`).
3. Відкрий **Terminal → New Terminal**.
4. Перевір, що у терміналі знаходишся в цій папці: `dir *.csproj` (PowerShell).
5. Введи `dotnet --version`. Для цього проєкту рекомендовано .NET SDK 8 та середовище виконання .NET 8. Якщо встановлена лише новіша версія SDK/Runtime, можна встановити .NET 8 або змінити `<TargetFramework>net8.0</TargetFramework>` у файлі `.csproj` на доступну версію, наприклад `net10.0` (за наявності SDK 10).
6. Запусти `dotnet run`.
7. Запусти автоматичні перевірки: `dotnet run -- --test`.

> **Якщо `Couldn't find a project to run`** — термінал відкрито не в тій папці. Відкрий саме `OnePieceLab2` або введи `dotnet run --project "повний\шлях\до\OnePieceLab2.csproj"`.

## Структура

- `Program.cs` — `Main`, три гравці та вісім матчів, перевірка помилки, статистика.
- `Game.cs` — абстрактна гра, унікальний ID, учасники, правила запису результатів.
- `StandardGame.cs` — звичайний матч: обидва грають на рейтинг.
- `TrainingGame.cs` — тренувальний матч: рейтинг кожного дорівнює нулю.
- `OneSidedGame.cs` — тільки обраний учасник грає на рейтинг.
- `GameFactory.cs` — фабрика всіх трьох типів ігор, повертає базовий `Game`.
- `GameAccount.cs` — абстрактний акаунт, історія ігор, обмеження рейтингу.
- `StandardAccount.cs` — звичайна формула: перемога +R, поразка −R.
- `ProtectedAccount.cs` — за поразку −ceil(R/2), за перемогу +R.
- `StreakAccount.cs` — з третьої рейтингової перемоги поспіль +10 до звичайних балів.
- `GameRecord.cs` — один запис у статистиці конкретного гравця.
- `SelfTests.cs` — автоматичні перевірки умов та крайніх випадків, зокрема виводу `GetStats()` і `null`-аргументів.

## Правила програми

- `CurrentRating` не може бути меншим за 1.
- Від'ємний рейтинг гри заборонено через `ArgumentOutOfRangeException`.
- Початковий рейтинг має бути не меншим за 1, а імена не можуть бути порожніми.
- Кожен матч має один ID. У двох гравців один і той самий матч відображається з однаковим ID.
- Індекс в історії обчислюється окремо для кожного гравця.
- Історія містить суперника, результат, тип матчу, рейтинг гри та фактичну зміну балів.
- Безрейтингові матчі рахуються як зіграні, але не змінюють рейтинг або серію рейтингових перемог.
- Непарна половина програшу для `ProtectedAccount` округлюється вгору (−11 для ставки 21).
- Якщо рейтинг після поразки мав би впасти нижче 1, він стає рівно 1.
- Матч не можна двічі записати одному гравцю або позначити перемогою для обох.
- Фабрика реалізує **upcasting** (похідний тип → базовий `Game`). У формулюванні завдання це названо «down cast», але технічно це upcasting.

## Теоретичні питання для захисту

1. **Наслідування:** створення нового класу на основі наявного, з повторним використанням його членів. Приклад: `StreakAccount : GameAccount`.
2. **Абстрактний метод:** метод без реалізації в базовому класі, який обов'язково реалізують конкретні наслідники. Приклад: `Game.GetRating()`.
3. **Віртуальний метод:** метод із реалізацією в базовому класі, яку наслідник за бажанням може змінити через `override`.
4. **`override` і `new`:** `override` поліморфно перевизначає віртуальний/абстрактний метод, а `new` приховує член базового класу; вибір прихованого члена залежить від типу посилання.
5. **Абстрактний і віртуальний метод:** абстрактний не має тіла й потребує реалізації, віртуальний має базову реалізацію, яку можна не змінювати.
6. **Інкапсуляція:** приховування внутрішнього стану через контроль доступу. У C# є `public`, `private`, `protected`, `internal`, `protected internal`, `private protected`, а також доступність `file` для деяких оголошень типів.
7. **Поліморфізм:** спільний інтерфейс роботи з об'єктами різних типів. `GameAccount` викликає власну реалізацію `CalculateRatingChange()` кожного нащадка.
8. **Статичний поліморфізм:** перевантаження методів (`GetStats()` і `GetStats(bool)`) або операторів; вибір здійснюється під час компіляції.
9. **Динамічний поліморфізм:** виклик `game.GetRating(player)` або `CalculateRatingChange` через базовий тип; реалізація обирається за фактичним типом об'єкта під час виконання.

## Що продемонструвати викладачу

1. Три класи акаунтів і різні формули (наслідування та поліморфізм).
2. Абстрактний `Game`, три його нащадки та фабрику.
3. Методи `WinGame(Game)` і `LoseGame(Game)`.
4. Перевірку неправильного рейтингу та обмеження рейтингу до 1.
5. Статистику всіх трьох персонажів (`GetStats`) та унікальні ID.
6. Результат `dotnet run -- --test`.
